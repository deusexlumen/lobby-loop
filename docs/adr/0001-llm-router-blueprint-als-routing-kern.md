# llm-router-blueprint als Routing-Kern des GM-Proxy

Der LLM-Verkehr des Spiels (Game-Master-Bewertungen, Beleidigungsfechten) läuft nicht direkt von der Engine zur Provider-API, sondern über einen lokalen Node-Proxy, der die Library `llm-router-blueprint` per `file:`-Dependency einbindet. Begründung: Free-Tier-Quota-Arbitrage über Model×Key-Kaskaden, persistente Quota-Sperren (RPM-Minuten- vs. RPD-Tages-Sperren, Zeitzone Pacific) und Provider-Chain-Orchestrierung sind gelöste Probleme dieser Library — ein Eigenbau im Spiel-Repo hätte sie neu erfunden und schlechter. Die Engine spricht ausschließlich mit dem Proxy auf `localhost`; Provider-Keys verlassen den Proxy nie. Konsequenz: Das Spiel ist an keinen Provider gebunden — Modellketten und Keys konfigurieren sich ausschließlich serverseitig per Umgebungsvariable.
