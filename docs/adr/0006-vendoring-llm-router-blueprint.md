# Vendoring: llm-router-blueprint zieht ins Repo

Die Dependency `llm-router-blueprint` zeigte als `file:../llm-router-blueprint` auf ein Sibling-Repo außerhalb des Projekts — jeder Clone oder CI-Lauf außerhalb der Entwicklermaschine brach bei `pnpm install`. Entscheidung: Vendoring eines Snapshots (Upstream-Commit `09922e2`) nach `vendor/llm-router-blueprint/`, package.json zeigt auf `file:vendor/llm-router-blueprint`. Alternativen und warum sie fielen: Kein Registry-Paket unter diesem Namen veröffentlicht (`pnpm view` → 404); eine Git-Dependency scheidet aus, weil Upstream `dist/` ignoriert, die package.json-Exports aber auf `./dist/index.js` zeigen — ein frischer Checkout wäre unbrauchbar. Akzeptierte Kosten: Der Router-Code muss bei Upstream-Änderungen manuell erneut gesnapshottet werden (Vendor-README dokumentiert Prozedur), und das Repo trägt ~189 KB fremden Code. Dafür ist das Projekt reproduzierbar klonbar, der Build versionierbar, und `pnpm install && pnpm test && pnpm run typecheck` laufen auf jeder Maschine grün.
